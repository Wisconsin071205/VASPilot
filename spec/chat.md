# 对话系统

对话及完整历史保存在实际配置目录的 `chat/<session_id>.json`。原有会话会在读取时补齐默认字段，无需手工迁移。超过 60 条的消息归档到 `archived_messages`，可见历史、搜索和导出仍包含这些消息；模型上下文使用近期消息和有界摘要。

## 请求与恢复

- 同一会话使用跨进程执行锁，一个时刻只能有一个回答在生成；独立会话最多并发 4 个请求。设置失败、断线和正常结束都释放资源。
- 页面为每次发送创建 `request_id`。问题及对应的助手消息在调用模型前一起保存。同一会话中已接收的请求标识不能再次执行，回答按请求标识更新。
- `turn` 保存请求标识、状态、当前阶段、工具名称及更新时间。最终结果先保存再发送完成事件。后台仍在运行时，刷新页面、切换会话或连接断开不会重新调用模型或工具。
- 浏览器丢失流连接时，通过 `chat.status` 读取原回答；应用进程退出后，失去执行锁的未完成回答显示为 `interrupted`。不会自动重新执行该回答中的工具。单阶段 HPC 任务仍由独立任务进程管理。
- 停止响应会发出取消信号。已经进入执行的单个操作可能先完成；停止不等于撤销远端作业。
- 生成期间不能清空、删除、压缩、重绑项目或分支该会话。清空与删除都要求先处理待确认的提交。
- 不完整或错误的模型响应不能触发本轮工具执行。历史已执行操作保留；用户可恢复输入并核对后继续。
- `workflow_prepare` 与 `research_prepare` 在返回成功前，将计划 ID 幂等关联到会话的 `workflow_plans`，不保存审批令牌。刷新或重连后，页面只读取原计划与当前运行状态：未运行时可审批，已有运行记录时仅显示状态并引导到任务中心。读取失败时禁止审批并提供核对提示；不会从聊天正文猜测计划归属。旧会话没有关联字段时按空列表处理，旧计划仍可在任务中心查看。

## 接口

`agent/chat` 保持 SSE 接口，增加 `activity` 和 `heartbeat` 事件。`final` 仍只发送一次；其结果已落盘。无会话标识的调用会创建会话，返回元信息中的标识可用于后续读取。

| 接口 | 参数 | 返回内容 |
| --- | --- | --- |
| `chat.sessions` | 可选 `query` | 按标题、项目及完整正文筛选的会话摘要 |
| `chat.load` | `session_id` | 完整消息、归档、本轮状态及 `workflow_plans` |
| `chat.status` | `session_id`，可选 `request_id` | 指定回答文本、执行状态及 `workflow_plans`，不执行模型或工具 |
| `chat.export` | `session_id` | Markdown 文件名和完整对话文本 |
| `chat.stop` | `request_id`，可选 `session_id` | 请求停止；指定会话后可向其他本机 UI 实例传递取消信号 |

保留既有的新建、重命名、分支、上下文压缩和删除接口。损坏记录不覆盖，读取及执行返回明确错误。

## 页面

会话栏支持搜索、重命名和导出；每条消息可复制。草稿和文本附件按会话保存在当前浏览器，浏览器拒绝保存或空间不足时明确提示。草稿不发送给模型，直到用户点击发送。更换浏览器或本机服务端口不会自动搬运浏览器草稿。

页面断线后的主要动作是读取原回答，不重新执行请求。切换会话保留草稿，并只渲染当前会话的回答。中文输入法组字确认的回车不会发送消息；查看旧消息时，新输出不强制滚动到底部。

## 验证

`tests/test_chat_reliability.py` 覆盖真实子进程同时保存、并发会话争用、请求重放、准备阶段失败释放资源、断线后完成、部分回答保存、首次探测期间取消及前端流解析、会话切换和草稿恢复。

`tests/test_provider_completion.py` 验证断流、长度限制及错误事件不会执行工具，并兼容有明确结束原因但没有 `[DONE]` 的 Chat Completions 服务。

`tests/test_chat_workflow_cards.py` 与 `tests/frontend/chat_workflow_cards.cjs` 覆盖计划关联的并发保存、会话隔离、刷新恢复、重复点击、状态查询失败及 Markdown 表头的语义化渲染。计划关联可随会话分支保留，但引用的是同一计划，不产生新的执行。
